# 恋面（れいめん）

Zoomのカジュアル面談を、恋愛ADVのような体験に変えるデスクトップアプリです。

作品名: **恋面（れいめん）**

授業の4人チーム開発用リポジトリです。

Electron + TypeScriptを中心としたMVPの技術検証を進めています。

## Product concept

### 就活恋愛ADV「恋面」

Zoomのカジュアル面談を、恋愛アドベンチャーゲームのような演出で記録・振り返りできるデスクトップアプリです。
Zoom本体はそのまま使い、面談中は自分のPC上のZoom表示に透明オーバーレイを重ねて、字幕やイベント演出を表示します。相手の映像に見た目の演出を重ねる場合も、まずは自分の画面上だけの表示とし、Zoomから相手へ送信するカメラ映像そのものは加工しません。

### Planned features

1. **Zoom専用恋愛フィルター**
   - 面談中のZoom画面に、恋愛ADV風の枠・ハート・背景演出を自分の画面上だけに表示する。
   - Zoomの送信映像を加工するバーチャルカメラ機能とは分け、Zoom本体の映像・音声送信には手を加えない。
2. **ADV風リアルタイム字幕**
   - Zoomの発言字幕を取得し、発言の意味を変えずに間・語尾・句読点だけを恋愛ゲーム風に整えて表示する。
   - 例: `新卒でも……Go、触れますよ……？`
3. **システムメッセージ演出**
   - `イベント発生！`、`企業情報GET！` などの通知を会話に合わせて表示する。
4. **面談ログ保存**
   - 字幕・話題・重要発言を、終了後の振り返り用に保存する。
5. **就活キャラクター「シュウカちゃん」**
   - 面談終了後に登場し、企業への好感度・企業理解度・印象に残った話題を総評する。
6. **企業好感度**
   - 面談内容とユーザー自身の反応から、その企業をどれくらい気になったかを数値化する。
7. **企業理解度**
   - 仕事内容・技術・働き方など、面談で得られた情報量を可視化する。
8. **AI要約**
   - 面談ログから、気になった点・魅力・確認したい点を整理し、シュウカちゃんの総評に利用する。
9. **デスクトップ常駐アプリ**
   - ElectronでZoom上に透明オーバーレイとサイドバーを表示し、Zoom操作はそのまま利用できるようにする。
   - 画面共有時に演出や面談ログが意図せず相手へ見えないよう、共有中の表示・非表示を設計し、対象OSで動作を検証する。

### MVP案

まずは、次の機能を最小構成として検証する。

1. Electronによる透明オーバーレイ
2. 字幕表示とADV風の間・句読点変換
3. イベント通知とハート演出
4. 面談ログのローカル保存
5. 面談後の要約・好感度・企業理解度の表示

Zoom RTMSとの接続やAI要約は、字幕モックでUIを検証した後に段階的に接続する。RTMSはZoom側のアプリ設定、Developer Pack、ホスト・管理者の許可が必要になる場合があるため、利用条件を実機で確認する。

### Privacy and operation notes

- 字幕の取得・保存・AI要約を開始する前に、利用者が状態を確認できる表示を用意する。
- 面談ログには個人情報や機密情報が含まれる可能性があるため、保存先・保持期間・削除方法を明確にする。
- 字幕の変換は発言の意味を変えず、演出上の間・語尾・句読点の調整に限定する。
- フィルターや恋愛ADV風の見た目は、初期仕様ではユーザーのローカル画面に重ねる演出とし、相手へ送るカメラ映像を加工しない。
- 画面共有時にオーバーレイが共有されるかはOS・共有方法に依存するため、共有中の挙動を実機で確認し、意図しない表示を防ぐ。
- Zoom字幕の取得方法、録音・保存時の参加者への同意、利用規約との整合性は実装前に確認する。

## Technical stack

デスクトップアプリはElectron + TypeScript、Zoom RTMS接続とAI・ログ処理はNode.js + TypeScript、データ基盤はSupabaseを採用する方針です。MVPではGoとRustは使用しません。

```text
Zoom RTMS -> Node.js / TypeScript -> Supabase Postgres
                    \-> Electron Overlay
                    \-> AI summary
```

Node.js / TypeScriptはZoom RTMSとの接続、字幕処理、イベント検出、AI連携、ElectronへのWebSocket配信を担当します。Zoom RTMSの公式Node.js SDKを利用し、受信するデータはMVPでは字幕中心に絞ります。

Electronは、透明・最前面・マウスイベント透過に対応したZoomオーバーレイ、会話ログ、企業カード、演出、面談後の総評画面を担当します。HTML / CSSで画面を構成するため、恋愛ADV風のテキストボックス、選択肢、ハート、キラキラ演出、テーマ変更を試作しやすい構成です。

SupabaseはPostgres、Auth、RLSを担当します。面談ログは同意した場合だけ保存し、音声・映像はMVPでは保存しません。RTMSの常時接続処理はSupabase Edge Functionsではなく、長時間稼働できるNode.jsサービスに置きます。

オーバーレイには、演出のON/OFF、クリック透過、ショートカットによる一発非表示、画面共有用の共有モードを用意します。Zoomのウィンドウ共有・画面全体共有で意図せずオーバーレイが映らないかは、対象OSで実機検証します。

詳細な責務、データモデル、API、セキュリティ、テスト、段階導入は [技術構成・アーキテクチャ設計](./docs/architecture-electron-node.md) を参照してください。

## Development policy

- 1 Issue = 1つの責務を基本にする
- 大きな設計判断は ADR に残す
- CodeRabbit は補助レビュアーとして使う
- test / lint / build など再現可能なCIを客観的な品質ゲートにする
- 4人チームなので、過度な分散システム化より責務境界の明確さを優先する
- ElectronのUIは、面談中の集中を妨げないように演出レベルを切り替えられる設計にする

## Development commands

よく使う開発コマンドは `Makefile` にまとめています。

```bash
make help
make setup
make run
make fmt
make test
make lint
make build
make check
```

現時点ではElectron / Node.jsプロジェクトの初期化前です。上記のMakefileコマンドは旧Go基盤の仮置きであり、`package.json`、Electronのメインプロセス、レンダラープロセス、Node.js RTMSサーバーの初期化時に更新します。
