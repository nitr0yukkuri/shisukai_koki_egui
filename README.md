# 恋面（れいめん）

Zoom面接などに向けて、1対1の面接を一人で練習し、会話ログとAIの振り返りから改善点を見つけるデスクトップアプリです。Zoomとは別の通常ウィンドウで起動し、Zoomの上に画面を重ねるアプリではありません。

作品名: **恋面（れいめん）**

授業の4人チーム開発用リポジトリです。

Electron + TypeScriptを中心としたMVPの技術検証を進めています。

## Product concept

### 一人で練習し、最後は自力で面接できるようにする

Zoomなどのオンライン面接や1対1の面接で緊張しやすい人が、一人で受け答えを練習し、会話ログとAIの振り返りから次の練習ポイントを見つけるアプリです。最初は用語解説や確認項目などの手助けを使い、練習を重ねるにつれてヒントを減らし、最終的にはアプリの手助けなしで自分の言葉で面接に臨めることを目指します。

恋愛ゲームのようなかわいい見た目は、緊張を和らげて練習を始めやすくするための任意の表現です。企業や面接相手を恋愛対象として扱ったり、好感度・合否をAIが採点したりすることは主目的にしません。

### 画面・操作イメージ

- Zoomとは別のウィンドウとして起動する、一人用の面接練習アプリ。Zoomの映像・音声を取得・加工したり、Zoom画面にオーバーレイを重ねたりせず、質問・回答・会話ログは本アプリ内で扱う。
- 練習モードを「ヒントあり」から「ヒント少なめ」「本番想定」へ段階的に切り替えられる。本番想定では面接中の補助を抑え、終了後に振り返る。
- 読み込んだ履歴書・ESに基づいてAIが質問や深掘り質問を出し、自分の回答と合わせて話者別ログに残す。面接後はAIが履歴書・ESを根拠に振り返りを返す。
- 中央に会話ログ、サイド領域に「AI用語解説」「企業チェック」「逆質問」のタブを置く。
- ログの各項目には3点リーダーを置き、編集・削除などの操作をまとめる。
- 会話ログ中の単語をマウスで選択すると青くハイライトし、その語句の要約・説明をAIに依頼してサイド領域に表示する。
- 技術名や仕事内容などのキーワードはログ中で見つけやすくする。まずは手動で強調・ピン留めできる形を基本とし、自動抽出は精度を検証してから追加する。
- 「あー」「えー」「あのー」などの言い淀みを、ログや音声認識結果から振り返る。回数・該当箇所・前回からの変化を示し、責めるのではなく次の練習に使える助言を返す。
- 企業チェック項目は面談中に確認・記入できる。逆質問は専用タブで一覧・追加・削除でき、面談後にも確認できるようにする。

### Planned features

#### MVPで優先する機能

1. **履歴書・ESの読み込み**: 自分の書類を練習セッションに読み込み、質問生成と振り返りの根拠にする。読み込んだ内容は練習前に確認・修正できるようにする。
2. **一人用のAI面接練習**: AIが履歴書・ESや応募職種に沿った質問・深掘り質問を出し、ユーザーは声に出して回答する。音声入力が使えない場合はテキスト入力でも練習でき、AIが使えない場合は一般的な質問リストを使う。
3. **話者別の会話ログ**: AI（面接官役）の質問と自分の回答を分けて残す。ログの3点リーダーから編集・削除できる。
4. **面接後のAIアドバイス**: 回答の伝わりやすさや具体例に加え、履歴書・ESと回答に大きな食い違いがないかを確認する。該当箇所を示し、「事実確認が必要な点」としてユーザーに確認を促す。合否や好感度は採点しない。
5. **言い淀みの振り返り**: 音声練習では「あー」「えー」「あのー」などの回数や該当箇所を示す。音声認識が言い淀みを正しく残すか先に技術検証し、認識結果はユーザーが修正できるようにする。
6. **練習サポートの段階設定**: 「ヒントあり」→「ヒント少なめ」→「本番想定」と支援を減らしていく。面接中の補助を減らし、面接後の振り返りは続けられる。
7. **選択語句のAI解説**: マウスで選択した語句を青く表示し、明示的な操作でAIに要約・説明を依頼する。結果は元の会話ログと区別して表示する。
8. **企業メモ・チェック・逆質問**: 仕事内容、技術、働き方、社風などをチェックリストとメモで整理する。逆質問は専用タブで追加・編集・削除し、質問済みかどうかも記録する。
9. **キーワードの視認性**: 技術名や重要語句をログ中で見つけやすくする。自動抽出が不安定なら手動ピン留めを用意する。

#### 追加候補

- 面談終了後に、ログ・メモ・チェック項目・逆質問をもとに振り返りを整理する。
- Zoom字幕の自動取り込み。Zoom RTMSの利用条件、ホスト側の許可、参加者への説明・同意を確認できた場合に限り検討する。
- 恋愛ゲームのようなかわいいテーマやキャラクターを、練習を始めやすくする任意の見た目として追加する。
- 企業ごとの履歴検索や複数端末での同期。

#### 将来構想

- 面接相手側にもアプリを導入してもらい、双方の会話ログを共有して相手からフィードバック・評価を受けられるようにする。
- これは一人用練習の完成後に検討する。相手の参加・録音・ログ共有への同意、閲覧範囲、削除権限を設計してから実装する。

### 練習ログ・音声の扱いについて

履歴書・ESの内容を使ってAI質問を個別化し、AIが質問を提示してユーザーが声に出して回答する一人練習を検証します。音声認識結果はユーザーが確認・修正でき、音声入力が使えない場合はテキスト入力に切り替えられるようにします。言い淀みの分析は、通常の文字起こしで「あー」「えー」が省かれる可能性があるため、音声からの検出精度を技術検証します。録音・音声処理を行う場合は、保存の有無とAIへの送信先を明示し、本人の操作と同意を前提にします。Zoom字幕の自動取り込みは、利用条件と参加者への説明・同意を確認した後の追加候補です。

### 履歴書・エントリーシートの扱い

- 履歴書・ESは質問の個別化と回答の振り返りにだけ使い、AIが参照した記述をユーザーに示す。
- AIが書類にない経歴や事実を作らないようにし、書類と回答の差は「矛盾」と決めつけず、ユーザーが確認するための候補として提示する。
- 連絡先など練習に不要な個人情報は、可能なら読み込み対象から除外・マスキングする。
- 元ファイルと抽出データの保存期間、AI送信の有無、削除方法を明示し、ユーザーが削除できるようにする。

### Privacy and operation notes

- 履歴書・ES、選択語句、回答ログ、音声をAIへ送る前に、送信内容と送信先が分かる操作・表示を用意する。
- 練習ログや応募書類には個人情報が含まれる。保存先・保持期間・削除方法を実装前に決める。
- 会話ログ、メモ、企業チェック項目、逆質問はユーザーが編集・削除できるようにする。
- Zoomと別ウィンドウでも、画面全体共有ではアプリが相手に見える可能性がある。共有前にアプリを隠す方法を用意する。
- AIの助言は練習用の参考情報として表示し、合否・適性を断定したり、言い淀みを人格評価に使ったりしない。

## Technical stack status

- **Desktop UI**: Electron + TypeScriptを現時点の候補とする。Zoomに重ねる透明オーバーレイではなく、Zoomの横で開く通常のアプリウィンドウを想定する。
- **AI・ログ処理**: AI APIキーをデスクトップアプリに埋め込まない。安全な接続方法とログ保存方式は、MVPのデータ取得方法に合わせて決める。
- **Node.js / Supabase**: 以前のオーバーレイ・Zoom RTMS前提の構成案に含まれていた。手入力中心のMVPに常時接続サーバーやクラウドDBが必要かは未確定であり、同期・認証・自動字幕取り込みの要件を確認してから採否を決める。
- **Go / Rust**: 現在のMVPでは採用を前提にしない。

従来の構成図・データモデル・API案は [技術構成・アーキテクチャ設計](./docs/architecture-electron-node.md) と [ADR-0003](./docs/adr/0003-use-electron-node-supabase.md) に残っていますが、いずれもオーバーレイ中心の旧スコープに基づきます。新しい機能範囲に対する技術判断は、内容を見直したうえで更新します。

## Development policy

- 1 Issue = 1つの責務を基本にする
- 大きな設計判断は ADR に残す
- CodeRabbit は補助レビュアーとして使う
- test / lint / build など再現可能なCIを客観的な品質ゲートにする
- 4人チームなので、過度な分散システム化より責務境界の明確さを優先する
- 面談中に視線移動・操作が増えすぎないよう、ログ・用語解説・企業チェック・逆質問の情報設計を優先する

## Development commands

よく使う開発コマンドは `Makefile` にまとめています。

```bash
make help
make setup
make run
make fmt
make test
make lint
make build
make check
```

現時点ではElectron / Node.jsプロジェクトの初期化前です。上記のMakefileコマンドは旧Go基盤の仮置きであり、`package.json`、Electronのメインプロセス、レンダラープロセス、Node.js RTMSサーバーの初期化時に更新します。
